Written for whoever picks the app up next (a person or an agent). Read
`CLAUDE.md` first; this is what changed today and why, plus what is known to
be open. Nothing here repeats what the code comments already say.

## What changed today, in one paragraph

The app used to drive herdr by exec'ing its CLI over SSH and parsing whatever
it printed, and learned what changed by polling every 2 to 3 seconds. It now
talks to herdr's JSON socket over the same SSH connection (a six-line python3
bridge on the host, or the fork's `herdr api-bridge`), and holds one
`events.subscribe` stream open per screen so the host says when an agent's
status flips or a turn ends. The CLI path is still there, byte for byte, for a
host with neither bridge. The transcript file is still the source of message
text; nothing on the socket carries it.

## The new pieces

| file | what it is |
|---|---|
| `src/lib/herdr/socket.ts` | `HerdrSocket`: one probe per host to pick a bridge and find the socket path; `call()` for one request, `subscribe()` for the stream. Typed errors carry herdr's own codes. |
| `src/lib/herdr/events.ts` | `EventFeed`: one subscription connection, re-opened when the pane set changes, reconnecting with backoff. Pure logic. |
| `src/features/useHostEvents.ts` | The hook that owns an `EventFeed` for a screen, gated like the poll (foreground and focused). Returns whether the stream is live. |
| `src/lib/herdr/client.ts` | `snapshot`, lists, `pane.read`, `send_keys`, workspace create/rename/close, `agent.wait`, `agent.prompt` go over the socket when the probe found a bridge, through the CLI otherwise. |
| `src/features/chats/useWorkspaces.ts`, `src/features/thread/useThread.ts` | Each event kicks the existing refresh loop (250 ms debounce). Poll rate drops to 30 s while the stream is live; the thread keeps 2 s while an agent is working, for the streaming preview. |
| `docs/research/herdr-socket-api-measurements.md` | Every number and shape above was measured, and this is where. |
| `src/lib/__tests__/socket.live.test.ts` | Runs the real thing against this machine's herdr: `HERDR_LIVE=1 HERDR_LIVE_PROMPT=1 npx jest socket.live`. Starts a Claude in `~/Developer/apptest`, prompts it, watches the stream, closes the workspace. |

## What a user should notice

- A chat's row flips to "working" and back, and its preview updates, when it
  happens rather than up to 3 s later.
- A sent message is confirmed by the host (`delivery: submitted`) instead of
  by a status watch that guessed.
- A chat opened, renamed or closed on the desktop appears or vanishes on the
  phone without a pull to refresh.
- Battery: on an idle screen the SSH connection carries one long-lived stream
  and a poll every 30 s instead of a round-trip every 2 to 3 s.
- The splash no longer shows the logo as a tile on black.

## Decisions that are not obvious from the code

- **`nc -U` was rejected**, not overlooked. macOS `nc` exits at stdin EOF, so
  any request slower than the write came back empty. The python bridge is 17 ms
  on loopback; the SSH round-trip dwarfs it.
- **A socket refusal is never retried through the CLI.** Both reach the same
  server. The one exception is `invalid_request` naming an unknown variant,
  which means the server never acted.
- **`pane.turns` is fork-only and carries no text** on this build. The
  transcript reader, its UTF-8 byte cursor and the session-id-is-the-filename
  rule all stay exactly as `CLAUDE.md` describes.
- **Keychain signing from an SSH session** needs the keychain unlocked in
  that session; unlocking it in a GUI terminal does not carry over. Three
  archives were lost to this before it was understood. See the memory note
  and `scripts/testflight.sh`.

## Known open items, ranked

1. **Nothing today was checked on a device.** The socket layer was verified
   against a real herdr through a local-exec transport and the unit suite, but
   the phone build 55/56 has not been opened by a person yet. First thing:
   open a chat, send a message, watch the list while an agent works.
2. **A superseded event stream lingers** until the host emits one more event
   on it (an async generator parked on a read cannot be interrupted). One idle
   bridge process per pane-set change; harmless, documented in `events.ts`.
3. **Linux hosts** get the python3 bridge; `/usr/bin/python3` exists on
   `spark`. A host with neither python3 nor the fork falls back to the CLI and
   polling, silently. Settings could say which path a host is on.
4. **`agent.start` over the socket is non-blocking** (returns `launch_pending`),
   unlike the CLI, so `startNamedAgent` still uses the CLI. Moving it means
   waiting for `pane.agent_detected` + first `idle` on the stream, which the
   live test already does.
5. Pre-existing, unrelated to today: issues #2 (host-side push sender never
   set up), #4 (no Android release path), #5 (Maestro gap on blocked replies),
   #18 (non-Claude agents), and the cmux backlog's T2-9 / T3-11..13.
